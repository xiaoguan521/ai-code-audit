# 八性 AI 代码检查：内网部署

本文是一套独立部署示例：在内网服务器新建目录，按下面内容创建配置文件即可，**不需要下载项目源码**。服务器需已安装 Docker 和 Docker Compose，并能访问 Git 仓库及内网模型服务。

实际使用以下两个内网镜像，请确认它们支持服务器的 CPU 架构。扫描器镜像应使用包含完整 DeepSeek Harness Headless、八性 Skill 和 Profile 的版本；若内网暂时只提供 Pi 镜像，可把 `AUDIT_AGENT_TYPE` 设为 `pi-docker` 作为回滚链路：

- `harbor.sjgjj.cn:10443/syxkit/ai-code-runner:latest-aicode`：调度器，拉取仓库、安排扫描并生成报告。
- `harbor.sjgjj.cn:10443/syxkit/deepseek-harness-audit:2026.11.23`：Harness 扫描器，调用完整 Agent Loop 审查代码。

## 1. 创建目录

以下以 `/opt/ai-code-audit` 为例，请使用有目录和 Docker 操作权限的账号：

```bash
mkdir -p /opt/ai-code-audit/{data,ssh,logs}
cd /opt/ai-code-audit
touch git-credentials
chmod 700 ssh
chmod 600 git-credentials
```

## 2. 创建配置文件

在 `/opt/ai-code-audit` 下创建以下五个文件，示例地址和密钥都需要替换。

### `compose.yaml`

```yaml
services:
  audit:
    image: harbor.sjgjj.cn:10443/syxkit/ai-code-runner:latest-aicode
    init: true
    environment:
      AUDIT_DATA_DIR: ${AUDIT_DATA_DIR}
      AUDIT_MODEL_NETWORK: ai-audit-model-net
      AUDIT_AGENT_TYPE: deepseek-harness
      AUDIT_SCANNER_IMAGE: harbor.sjgjj.cn:10443/syxkit/deepseek-harness-audit:2026.11.23
      AUDIT_MODEL_ENV_PATH: /run/secrets/model.env
      AUDIT_HARNESS_BIN: dsh
      AUDIT_HARNESS_ARGS: '["headless", "--json", "--permission-mode", "read-only", "--approval-policy", "never"]'
      AUDIT_SUMMARY_ENABLED: "false"
      TZ: Asia/Shanghai
    volumes:
      - "${AUDIT_DOCKER_SOCKET}:/var/run/docker.sock"
      - "${AUDIT_DATA_DIR}:${AUDIT_DATA_DIR}"
      - "./projects.csv:/opt/ai-code-audit/config/projects.csv:ro"
      - "./model.env:/run/secrets/model.env:ro"
      - "./git-credentials:/run/secrets/git-credentials:ro"
      - "./ssh:/root/.ssh:ro"
    networks:
      - model

networks:
  model:
    name: ai-audit-model-net
```

### `.env`

```dotenv
AUDIT_DATA_DIR=/opt/ai-code-audit/data
AUDIT_DOCKER_SOCKET=/var/run/docker.sock
```

`AUDIT_DATA_DIR` 必须是宿主机上的绝对路径，且与第 1 步创建的目录一致；如果 Docker socket 不在示例路径，请改为实际路径。

### `model.env`：模型地址和密钥

```dotenv
OPENAI_BASE_URL=http://model.internal.example.com:8000/v1
OPENAI_MODEL=qwen3-coder
OPENAI_API_KEY=替换为实际密钥
```

填写容器能访问的 OpenAI 兼容接口地址、模型名和 Key，值不加引号。`127.0.0.1` 在容器内指容器自身，模型在其他机器或宿主机时需填写实际可访问的地址。

Harness 使用完整 Headless Agent Loop，Runner 只传入一个顶层审查任务，不按八个维度拆分，也不介入 Harness 的规划、工具调用、多轮推理或子 Agent。`model.env` 的变量按 Harness Profile 要求填写；若该 Harness 通过 OpenAI 兼容接口调用模型，可继续使用 `OPENAI_BASE_URL`、`OPENAI_MODEL` 和 `OPENAI_API_KEY`。Pi 回滚链路仍使用同一组模型变量。

`AUDIT_HARNESS_ARGS` 必须是 JSON 数组，不能写成 shell 命令字符串。Harness 最终事件必须有成功的 `final.reason.kind`，并返回符合审查 Markdown 契约的完整 64 项报告；否则该项目会标记为 `unverified`，不会进入评分。Runner 默认把顶层任务作为 `dsh` 的参数传入，固定版本若只支持 stdin 时再在设置中补充 `prompt_mode: "stdin"`。

如需启用第二阶段总结，把 `AUDIT_SUMMARY_ENABLED` 改为 `true`。Harness 模式下它默认复用扫描镜像、网络和模型环境，但只挂载审查产物，不挂载源码；总结失败会自动降级为程序摘要，不会改变审查评分。

### `projects.csv`：多个仓库和分支

```csv
project_id,project_name,git_url,branch,status
order-main,订单服务主分支,https://git.example.com/team/order.git,main,在研
order-dev,订单服务开发分支,https://git.example.com/team/order.git,develop,在研
inventory-main,库存服务,https://git.example.com/team/inventory.git,main,在研
```

每行配置一个仓库分支，`project_id` 不能重复，`status` 填 `在研` 才会扫描。同一仓库的不同分支使用不同 ID；以后换仓库地址时也请使用新 ID。不要把 Git 密码写进 `git_url`。

### `git-credentials`：Git 用户名和密码

HTTPS 私有仓库每个地址填写一行；同一仓库的不同分支共用一行：

```text
https://用户名:密码或只读令牌@git.example.com/team/order.git
https://用户名:密码或只读令牌@git.example.com/team/inventory.git
```

主机、端口和仓库路径必须与 `projects.csv` 一致。密码或令牌中的 `@`、`:`、`/`、`%` 等特殊字符需要 URL 编码；Git 服务要求使用令牌时填写只读令牌。使用 SSH 时，将仓库地址改成 SSH 地址，并把私钥和经过核验的 `known_hosts` 放入 `ssh/`；`git-credentials` 可以为空，但文件要保留。

两个凭据文件都是明文，设置权限并限制访问：

```bash
chmod 600 model.env git-credentials
```

## 3. 准备镜像

**服务器可以访问 Harbor 时**，在服务器执行；如果需要认证，请先执行 `docker login harbor.sjgjj.cn:10443`：

```bash
docker pull harbor.sjgjj.cn:10443/syxkit/ai-code-runner:latest-aicode
docker pull harbor.sjgjj.cn:10443/syxkit/deepseek-harness-audit:2026.11.23
```

**服务器无法访问 Harbor 时**，在能访问 Harbor 且与服务器架构相同的机器执行上面两条 `docker pull`，然后打包：

```bash
docker save -o ai-code-audit-images.tar \
  harbor.sjgjj.cn:10443/syxkit/ai-code-runner:latest-aicode \
  harbor.sjgjj.cn:10443/syxkit/deepseek-harness-audit:2026.11.23
```

将 `ai-code-audit-images.tar` 传到内网服务器后导入：

```bash
docker load -i ai-code-audit-images.tar
```

## 4. 试跑和正式扫描

```bash
cd /opt/ai-code-audit
docker compose config --quiet

# 检查仓库和分支；会拉取代码，但不调用模型
docker compose run --rm --pull never audit --dry-run

# 先全量扫描一个项目，order-main 替换成实际 project_id
docker compose run --rm --pull never audit --only order-main --force-full

# 扫描全部在研项目
docker compose run --rm --pull never audit
```

试跑时确认项目数不是 0。调度器每次执行完成后会退出；首次和默认每周六全量扫描，有新提交时尝试增量扫描，无变化时可复用结果。`data/` 保存代码副本和历史状态，不要随意删除；扫描专用副本会被重置和清理，不要在其中保存人工修改。

报告位置：

```text
/opt/ai-code-audit/data/output/reports/<日期>/   扫描报告
/opt/ai-code-audit/data/output/dashboard/index.html  静态看板
/opt/ai-code-audit/data/output/results/<日期>/_run.json  运行状态
/opt/ai-code-audit/data/output/artifacts/<日期>/<项目ID>/audit.md、audit.json、summary.md  原始审查、校验结果和独立总结
```

报告中的 `audit_status` 与 `summary_status` 分开记录：Harness 进程成功但 Markdown 未通过 64 项覆盖或证据校验时，项目仍是 `unverified`，不计入有效评分；独立 Summary Agent 失败时只显示 `fallback`，不影响已经验证的审查评分。

## 5. 每天定时运行

在运行账号执行 `crontab -e`，例如每天 01:30 运行：

```cron
30 1 * * * cd /opt/ai-code-audit && /usr/bin/flock -n /opt/ai-code-audit/audit.lock /usr/bin/docker compose run --rm --pull never -T audit >> /opt/ai-code-audit/logs/audit.log 2>&1
```

先用 `command -v docker` 和 `command -v flock` 确认命令路径，并确认服务器 cron 的时区。手动运行时避免与定时任务重叠。

调度容器通过 Docker socket 启动扫描容器，拥有宿主机 Docker 的控制权限，请在可信服务器上运行；Compose 网络本身不会限制出站访问，需按内网要求配置防火墙。
