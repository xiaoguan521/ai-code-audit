# 内网部署与运维

日常部署以同一版本的仓库 `compose.yaml` 和 [新镜像配置与迁移说明](DeepSeek-Harness新镜像配置与迁移说明.md) 为准。需要 Docker、Docker Compose、可访问的 Git 仓库和支持工具调用的 OpenAI 兼容模型服务。

## 离线导入两个镜像

在能够访问镜像仓库、且能拉取目标架构镜像的机器上，将下面的版本替换为同一构建发布的实际标签：

```bash
docker pull ghcr.io/xiaoguan521/ai-code-audit:<版本>
docker pull ghcr.io/xiaoguan521/ai-code-audit-runner:<版本>
docker save -o ai-code-audit-images.tar \
  ghcr.io/xiaoguan521/ai-code-audit:<版本> \
  ghcr.io/xiaoguan521/ai-code-audit-runner:<版本>
```

将包传到内网，执行 `docker load -i ai-code-audit-images.tar`；或由运维同步到 Harbor，再将 `.env` 的两个镜像地址改为 Harbor 地址。运行 `docker image inspect <镜像名>:<版本>` 可确认本机已有对应镜像。保存和导入不能代替在目标架构上的实际运行验证。

## 配置与运行

使用同版本 `compose.yaml`、`.env`、`model.env`、`config/projects.local.csv` 和 `secrets/`。首次部署可先执行一键初始化与环境自检：

```bash
# 一键生成缺失的 .env（自动随机生成 AUDIT_WEB_TOKEN）、model.env、projects.local.csv 及 secrets 占位目录（不覆盖已有文件）
python3 runner/doctor.py --init

# 部署前环境自检（可选加 --check-model 探测模型服务连通性）
python3 runner/doctor.py
```

详细字段与千问示例见[配置与迁移说明](DeepSeek-Harness新镜像配置与迁移说明.md)。模型凭据和 Git 凭据应仅供运行账号读取，扫描网络需能到达模型服务。

```bash
# 查看最终生效的编排配置；输出可能包含环境配置，应注意访问权限
docker compose config

# 常驻启动 Web 看板（复用 Runner 镜像；访问需输入 .env 中的 AUDIT_WEB_TOKEN）
docker compose up -d web

# 扫描两个项目并生成本次整体报告
docker compose run --rm --pull never -T audit --only project-a project-b

# 每日快速巡检，不生成详细证据
docker compose run --rm --pull never -T audit --fast

# 汇总之前分别扫描的项目最近报告
docker compose run --rm --pull never -T audit --only project-a project-b --summary-only
```

日志中会打印运行编号和整体报告路径。项目 Markdown 位于 `<data>/output/reports/<日期>/<运行编号>/`，运行状态和脱敏事件位于对应 `results/` 子目录。两条不同项目的扫描命令可以同时运行；相同项目会互斥。按模型服务的实际能力设置 `AUDIT_MAX_PARALLEL` 和 `AUDIT_MAX_MODEL_CONCURRENCY`。

Semgrep 未配置离线规则时跳过，不影响其他预扫描和审查。使用 `AUDIT_SEMGREP_RULES_DIR` 可指定已挂载、可读的本地规则目录。扫描专用 `<data>/work/` 由 Runner 更新和清理，不要存放人工修改。

Runner 镜像内置了新版 **Web 看板与报告平台**（通过 `docker compose up -d web` 常驻启动，读取 `_run.json` 与 Markdown 报告），无需生成旧版静态看板文件。在 Web 的「扫描与配置」页可直接可视化配置每日/每周定时扫描（配置持久化在 `<data>/output/state/schedule.json`，依赖 `web` 容器常驻运行），并实时查看各项目扫描进度与日志。模型的执行完成状态不等于报告已经被人工复核；重要结论需结合报告范围和证据确认。

## 沿用旧版独立部署目录

如果现场使用的是 `projects.csv`、`git-credentials` 和 `ssh/`，不必调整成仓库目录结构。可以使用下面的独立 `compose.yaml`；`.env` 和 `model.env` 的字段仍按迁移说明配置。务必将 `AUDIT_DATA_DIR` 配成宿主机绝对路径，且保持宿主机与容器中的路径相同。

```yaml
x-runner-common: &runner-common
  image: ${AUDIT_RUNNER_IMAGE:?请设置 Runner 镜像}
  init: true
  environment:
    AUDIT_DATA_DIR: ${AUDIT_DATA_DIR:?请设置绝对路径}
    AUDIT_MODEL_NETWORK: ${AUDIT_MODEL_NETWORK:-ai-audit-model-net}
    AUDIT_AGENT_TYPE: deepseek-harness
    AUDIT_SCANNER_IMAGE: ${AUDIT_SCANNER_IMAGE:?请设置扫描镜像}
    AUDIT_MODEL_ENV_PATH: /run/secrets/model.env
    AUDIT_HARNESS_BIN: dsh
    AUDIT_HARNESS_ARGS: '["headless","--json","--permission-mode","read-only","--approval-policy","never"]'
    AUDIT_MAX_PARALLEL: ${AUDIT_MAX_PARALLEL:-2}
    AUDIT_MAX_MODEL_CONCURRENCY: ${AUDIT_MAX_MODEL_CONCURRENCY:-2}
    AUDIT_PER_PROJECT_TIMEOUT_SEC: ${AUDIT_PER_PROJECT_TIMEOUT_SEC:-3600}
    AUDIT_FAST_MODE: ${AUDIT_FAST_MODE:-false}
    AUDIT_SUMMARY_ENABLED: ${AUDIT_SUMMARY_ENABLED:-true}
    AUDIT_SEMGREP_RULES_DIR: ${AUDIT_SEMGREP_RULES_DIR:-}
    AUDIT_WEB_TOKEN: ${AUDIT_WEB_TOKEN:-}
    TZ: Asia/Shanghai
  volumes:
    - "${AUDIT_DOCKER_SOCKET:-/var/run/docker.sock}:/var/run/docker.sock"
    - "${AUDIT_DATA_DIR}:${AUDIT_DATA_DIR}"
    - "./projects.csv:/opt/ai-code-audit/config/projects.csv:ro"
    - "./model.env:/run/secrets/model.env:ro"
    - "./git-credentials:/run/secrets/git-credentials:ro"
    - "./ssh:/root/.ssh:ro"
  networks:
    - model

services:
  audit:
    <<: *runner-common

  web:
    <<: *runner-common
    entrypoint: ["python3", "/opt/ai-code-audit/runner/web_server.py", "--host", "0.0.0.0", "--port", "8787"]
    ports:
      - "${AUDIT_WEB_PORT:-8787}:8787"
    restart: unless-stopped

networks:
  model:
    name: ${AUDIT_MODEL_NETWORK:-ai-audit-model-net}
```

即使只使用 HTTPS Git 凭据，也要先准备 `ssh/` 目录；只使用 SSH 时也要准备空的 `git-credentials` 文件，使挂载目标存在。
