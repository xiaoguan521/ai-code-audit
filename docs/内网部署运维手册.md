# 八性 AI 代码检查：内网部署与运维手册

本文针对本项目当前的 Docker Compose 部署方式，适用于能访问内部 Git 服务和 OpenAI 兼容模型服务的 Linux 服务器。示例域名、账号和密钥均需替换。

> 本次 Compose、调度器和工作流的改动需要先进入 GitHub 默认分支并成功运行 `Build image`，调度镜像才会发布。工作流成功前，请使用包含这些改动的源码在联网机器本地构建调度镜像；直接从 GitHub 克隆旧版本可能找不到这些文件。

> 当前编写环境未连接 Docker daemon，本文中的镜像构建、离线导入和模型连通性尚未在目标服务器实测；上线时请按第 6 节先验收单个项目。

## 1. 部署方式与镜像

| 组件 | 镜像 | 用途 |
|---|---|---|
| 调度器 | `ghcr.io/xiaoguan521/ai-code-audit-runner:main` | 拉取各 Git 分支、安排扫描、保存状态和生成报告 |
| 扫描器 | `ghcr.io/xiaoguan521/ai-code-audit:main` | Qwen Code 扫描镜像；每个项目的实际审查使用该镜像 |

两个镜像由同一工作流构建，支持 `linux/amd64` 和 `linux/arm64`。`:main` 会随发布更新；为固定部署版本，建议选择同一次成功工作流生成的两个 `:sha-<提交短 SHA>` 标签，或使用同一版本标签。离线导入的两个镜像标签必须分别与 `.env` 里的 `AUDIT_SCANNER_IMAGE`、`AUDIT_RUNNER_IMAGE` **完全一致**。

执行链路：

```text
调度容器 audit ──只读凭据──> 内网 Git，按仓库和分支拉取代码
       │
       ├──通过本机 Docker 启动扫描容器 ──> 内网模型 API
       │                              仓库和上下文均以只读方式挂载
       └──处理结果 ──> 报告、看板和历史状态
```

这是一次性批量任务，不是常驻 Web 服务：`docker compose run` 执行完后调度容器会退出。需要每天扫描时另行配置定时任务。

## 2. 部署前检查

1. Linux 服务器已安装并启动 Docker Engine 和 Docker Compose 插件；部署账号可以访问 Docker socket。通过 Docker socket 控制容器相当于拥有宿主机的高权限，请使用可信运行机和受控账号。
2. 服务器能访问所列 Git 仓库及其指定分支；扫描容器能访问内网模型 API。域名、DNS、端口、代理和防火墙策略需在内网确认。
3. 模型服务提供与 Qwen Code 使用方式兼容的 OpenAI API、模型名及 API Key。示例以 `/v1` 为基础路径，最终以实际服务为准。
4. 确认足够的磁盘、CPU 和内存。当前默认并发数为 2，每个扫描容器最多配置 6 GiB 内存和 2 个 CPU；这不是预留值，还需为系统、Git 副本和其他服务留出余量。
5. Compose 会创建 `ai-audit-model-net`，但网络名称本身不限制出站访问。当前调度容器与扫描容器都接入该网络：网络策略既要允许调度器访问 Git，也要限制扫描容器只访问获准的模型服务，需结合实际防火墙和网络拓扑验证。

在目标机检查：

```bash
uname -m                         # x86_64 对应 amd64；aarch64 对应 arm64
docker version                   # Client 和 Server 均应正常
docker compose version
docker info >/dev/null
```

采用本机 Docker daemon：`AUDIT_DATA_DIR` 必须是 daemon 所在宿主机的绝对路径。若使用远程 Docker daemon，客户端本地目录不会自动成为 daemon 主机的挂载源，需重新设计文件共享。

## 3. 无外网时：在联网构建机准备镜像包

需要两份材料：**部署源码包**和**镜像包**。源码包不包含真实模型密钥、Git 凭据或运行数据；实际配置在内网服务器上填写。目标服务器还需要事先安装 Docker 和 Compose，它们不包含在源码包里。

若从已经包含本次改动的 Git 版本获取源码，也可执行 `git archive --format=tar.gz -o ai-code-audit-deploy-src.tar.gz HEAD`，再用 `sha256sum ai-code-audit-deploy-src.tar.gz > ai-code-audit-deploy-src.tar.gz.sha256` 生成源码包校验文件。`git archive` 只包含已提交内容，不包含未提交的 Compose 或调度器改动。

建议使用与目标机架构相同的联网 Linux 构建机。例如目标是 `x86_64`，构建机也使用 `x86_64`；目标是 `aarch64`，构建机也使用 `aarch64`。若跨架构构建，必须自行配置对应的 Buildx / QEMU，并分别确认两个镜像的架构。

把 `ai-code-audit-deploy-src.tar.gz` 和同名 `.sha256` 文件复制到构建机，在源码包所在目录执行：

```bash
sha256sum -c ai-code-audit-deploy-src.tar.gz.sha256
mkdir -p ai-code-audit-build
tar -xzf ai-code-audit-deploy-src.tar.gz -C ai-code-audit-build
cd ai-code-audit-build

# 使用同一次成功工作流对应的镜像标签；以下示例为 main。
# 固定版本时可将两个标签都替换为相同的 sha-<提交短 SHA>。
SCANNER_IMAGE=ghcr.io/xiaoguan521/ai-code-audit:main
RUNNER_IMAGE=ghcr.io/xiaoguan521/ai-code-audit-runner:main

docker pull "$SCANNER_IMAGE"
docker pull "$RUNNER_IMAGE"

# 输出的 linux/amd64 或 linux/arm64 必须与目标机一致。
docker image inspect "$SCANNER_IMAGE" --format '{{.Os}}/{{.Architecture}}'
docker image inspect "$RUNNER_IMAGE" --format '{{.Os}}/{{.Architecture}}'

# 同时导出扫描器和调度器；预留足够磁盘存放未压缩 tar。
docker image save -o ai-code-audit-images.tar "$RUNNER_IMAGE" "$SCANNER_IMAGE"
gzip ai-code-audit-images.tar
sha256sum ai-code-audit-images.tar.gz > ai-code-audit-images.tar.gz.sha256
```

若调度镜像尚未发布，或需要修改调度配置，可在联网构建机用 `docker build -f docker/Dockerfile.runner -t "$RUNNER_IMAGE" .` 本地构建，再导出。这需要从 Docker Hub 获取 `docker:27-cli`，并从 Alpine 软件源安装 Python、Git 和 SSH 客户端。扫描镜像不包含批量调度程序，所以不能只导出扫描镜像。镜像保存与导入方式可参考 [Docker 官方文档](https://docs.docker.com/reference/cli/docker/image/save/)。

版本 tag 的工作流成功后，也可从 GitHub Release 分别下载目标架构的扫描镜像和调度镜像离线包及其 `.sha256`。例如版本 `v1.2.0`、架构 `amd64` 需要 `ai-code-audit_v1.2.0_amd64.tar.gz` 和 `ai-code-audit-runner_v1.2.0_amd64.tar.gz`；校验后分别 `docker image load -i`，并将 `.env` 中两个 GHCR 镜像标签都设置为 `:1.2.0`。

通过单位允许的方式，将以下文件传入内网服务器的同一目录：

```text
ai-code-audit-deploy-src.tar.gz
ai-code-audit-deploy-src.tar.gz.sha256
ai-code-audit-images.tar.gz
ai-code-audit-images.tar.gz.sha256
```

**如果目标机能访问 GHCR**，也可以在目标机解压源码后直接执行上面的两条 `docker pull`，不需要镜像包。完全离线时不要在目标机使用 `--build` 或 `docker compose pull`。

## 4. 内网服务器：导入和初始化

以下示例以 `/opt/ai-code-audit` 存放部署文件，以 `/data/ai-code-audit` 存放代码副本及报告。以实际已授权部署账号执行；如需 `sudo` 才能操作 Docker，应使用同一权限方式运行后续 Docker 命令。

```bash
cd /path/to/offline-files
sha256sum -c ai-code-audit-deploy-src.tar.gz.sha256
sha256sum -c ai-code-audit-images.tar.gz.sha256

# 仅需首次创建；将目录所有权交给当前部署账号。
sudo install -d -m 0750 -o "$(id -u)" -g "$(id -g)" /opt/ai-code-audit /data/ai-code-audit
tar -xzf ai-code-audit-deploy-src.tar.gz -C /opt/ai-code-audit
docker image load -i ai-code-audit-images.tar.gz

docker image inspect ghcr.io/xiaoguan521/ai-code-audit-runner:main --format '{{.Os}}/{{.Architecture}}'
docker image inspect ghcr.io/xiaoguan521/ai-code-audit:main --format '{{.Os}}/{{.Architecture}}'

cd /opt/ai-code-audit
umask 077
cp .env.example .env
cp config/projects.compose.example.csv config/projects.local.csv
cp docker/model.env.example model.env
mkdir -p secrets/ssh /data/ai-code-audit/logs
cp docker/git-credentials.example secrets/git-credentials
chmod 700 secrets secrets/ssh
chmod 600 .env model.env config/projects.local.csv secrets/git-credentials
```

初始化命令适用于新部署目录；已有配置时先备份，不要直接覆盖。不要把本机上为 OrbStack 等环境配置的 `.env` 直接带到服务器，服务器应根据自身 Docker socket 和路径重新填写。

## 5. 填写配置

### 5.1 Compose 和数据路径

编辑 `/opt/ai-code-audit/.env`，示例：

```dotenv
AUDIT_DATA_DIR=/data/ai-code-audit
AUDIT_MODEL_NETWORK=ai-audit-model-net
AUDIT_SCANNER_IMAGE=ghcr.io/xiaoguan521/ai-code-audit:main
AUDIT_RUNNER_IMAGE=ghcr.io/xiaoguan521/ai-code-audit-runner:main
AUDIT_DOCKER_SOCKET=/var/run/docker.sock
```

- `AUDIT_DATA_DIR` 是宿主机绝对路径，需提前创建并有足够空间；调度容器与 Docker daemon 使用相同路径访问项目副本。
- `AUDIT_MODEL_NETWORK` 是 Compose 管理的网络名。模型地址必须能从这个网络访问；修改后需要按实际网络重做验证。
- `AUDIT_SCANNER_IMAGE` 必须与加载到目标机的镜像标签一致。使用内部镜像仓库时也需确保两个位置的标签一致。
- `AUDIT_RUNNER_IMAGE` 是调度镜像，必须与加载到目标机的调度镜像标签一致。
- `AUDIT_DOCKER_SOCKET` 填目标机实际 socket；rootless Docker 等环境可能不是示例路径。部署账号须具备该 socket 的访问权限。

### 5.2 多个 Git 仓库和分支

编辑 `/opt/ai-code-audit/config/projects.local.csv`。示例已有两个仓库，其中订单服务扫描两个分支。重点字段如下：

| 字段 | 填写方式 |
|---|---|
| `project_id` | 每一行唯一且长期稳定，建议只用字母、数字、中划线或下划线；同一仓库不同分支也用不同 ID |
| `project_name` | 报告展示名 |
| `git_url` | 不带账号和密码的 Git HTTPS 或 SSH 地址 |
| `branch` | 要扫描的真实分支，如 `main`、`develop` |
| `status` | 默认只扫描值为 `在研` 的行 |

保留 CSV 原有表头和列数，按示例替换 `git.example.com`、仓库路径和分支；含逗号的单元格需按 CSV 规则加双引号。更换仓库地址时使用新的 `project_id`：现有项目 ID 关联已缓存的仓库副本，不会自动改为新地址。不要将账号、密码或令牌写入 `git_url`，因为仓库地址会被写入扫描结果。

### 5.3 内网模型地址与密钥

编辑 `/opt/ai-code-audit/model.env`：

```text
OPENAI_BASE_URL=http://model.internal.example.com:8000/v1
OPENAI_MODEL=qwen3-coder
OPENAI_API_KEY=替换为实际密钥
```

地址、模型名和密钥替换为实际值，按 Docker `--env-file` 格式填写，不要在值外加引号。`127.0.0.1` 在扫描容器内指容器自身；若模型在宿主机或其他服务器，请填写容器能访问的 IP 或域名。该文件是明文，只允许授权人员读取；密钥也会作为容器环境变量提供给扫描容器，能管理 Docker 的人员可能查看到它。

### 5.4 Git 用户名和密码 / 令牌

HTTPS 私有仓库：编辑 `/opt/ai-code-audit/secrets/git-credentials`，每个仓库一行，例如：

```text
https://demo-user:demo-token@git.example.com/trade/order-service.git
https://demo-user:demo-token@git.example.com/supply/inventory-service.git
```

将示例用户名和令牌替换为实际的只读账号及密码或访问令牌；服务器要求令牌时使用令牌。主机、端口和仓库路径须与 CSV 中的 HTTPS 地址匹配；同一仓库不同分支共用一行。用户名或密码中的 `@`、`:`、`/`、`%` 等特殊字符须先做 URL 编码。此文件采用 Git 的明文凭据格式，保留 `600` 权限并避免放进聊天、工单或源码仓库；格式说明见 [Git 官方文档](https://git-scm.com/docs/git-credential-store)。

SSH 私有仓库：将 CSV 的 `git_url` 改为 SSH 地址，私钥和经核验的 `known_hosts` 放到 `/opt/ai-code-audit/secrets/ssh/`，私钥权限为 `600`。如为多个服务器分别指定密钥，可在该目录的 `config` 中设置 `IdentityFile /root/.ssh/密钥文件名`。任务为非交互运行；需要 SSH agent 的带口令私钥还需额外配置 agent socket，当前模板没有自动映射。只用 SSH 时仍保留 `secrets/git-credentials` 文件，可将其清空。

### 5.5 扫描参数

`config/settings.json` 中的并发、超时、镜像内存和 CPU 限额在构建调度镜像时被复制进镜像。需要调整时，应在联网构建机修改后重新构建并导出调度镜像，再在内网导入；仅修改服务器上的该文件不会改变已构建的调度镜像。

Compose 启动时会使用 `.env` 覆盖运行目录、扫描镜像、模型环境文件位置和网络名；这些字段不需要在 `config/settings.json` 里重复修改。预扫描工具为可选项，当前调度镜像没有默认安装 cloc、gitleaks、semgrep、lizard；未安装时会跳过相应工具。

## 6. 启动和验收

确认已替换全部示例值、镜像和配置文件存在：

```bash
cd /opt/ai-code-audit
docker compose config --quiet
docker image inspect ghcr.io/xiaoguan521/ai-code-audit-runner:main >/dev/null
docker image inspect ghcr.io/xiaoguan521/ai-code-audit:main >/dev/null
```

### 6.1 检查 Git 和扫描计划

```bash
docker compose run --rm --pull never audit --dry-run
```

该命令会连接 Git、克隆或更新 `AUDIT_DATA_DIR/work/` 中的**扫描专用副本**，并输出每个项目的提交和扫描计划；不会调用模型，但会写入当天的 `_run.json`。检查项目数和分支都正确，避免 `status` 不为 `在研` 导致 0 个项目仍返回成功。扫描副本会被程序 `git reset --hard` 和 `git clean`；不要在该目录保存人工修改。

如需单独测试某个 HTTPS 仓库的认证和分支，可替换下面的地址及分支：

```bash
docker compose run --rm --pull never -e GIT_TERMINAL_PROMPT=0 --entrypoint git audit \
  ls-remote --heads https://git.example.com/trade/order-service.git main
```

正常时输出该分支的提交 SHA；不要把用户名和密码拼进这条命令。调度容器内的 Git 会按上面的凭据文件匹配。

### 6.2 检查模型网络（可选）

先执行过上面的 Compose 试跑，以创建模型网络。以下命令使用实际扫描镜像和 `model.env` 请求模型服务的 `/models`，不打印 API Key：

```bash
docker run --rm --pull never --network ai-audit-model-net --env-file ./model.env \
  --entrypoint node ghcr.io/xiaoguan521/ai-code-audit:main \
  -e 'fetch(process.env.OPENAI_BASE_URL.replace(/\/+$/, "") + "/models", {headers: {Authorization: "Bearer " + process.env.OPENAI_API_KEY}, signal: AbortSignal.timeout(10000)}).then(r => {console.log("HTTP", r.status); if (!r.ok) process.exitCode = 1}).catch(e => {console.error(e.message); process.exitCode = 1})'
```

如果 `.env` 里修改了网络名或镜像名，这里也要相应替换。部分兼容服务不提供 `/models`，因此 404 不一定代表推理接口不可用；最终以单项目真实扫描为准。此检查会访问模型服务，但不会执行代码审查。

### 6.3 先扫一个项目，再扫全部

`order-main` 是示例，请替换为实际 CSV 中的项目 ID：

```bash
docker compose run --rm --pull never audit --only order-main --force-full
docker compose run --rm --pull never audit
```

第一条强制全量扫描一个项目；第二条按配置扫描全部在研项目，自动选择全量、增量或复用。`--pull never` 限制 Compose 不拉取调度镜像；调度器启动扫描容器时仍由 Docker 使用本地扫描镜像，若标签不存在可能尝试拉取，因此离线部署前必须完成上面的 `docker image inspect`。

任务退出后检查 `/data/ai-code-audit/output/`：

```text
output/results/<日期>/_run.json       当次运行状态、项目数和错误摘要
output/results/<日期>/<项目ID>.json   结构化结果
output/results/<日期>/<项目ID>.error.txt  失败时的错误详情
output/reports/<日期>/<项目ID>.md     单项目报告
output/reports/<日期>/_summary.md     日汇总
output/dashboard/index.html          静态看板
output/state/                         下次增量或复用所需状态
```

正常退出码为 0；项目失败时为非 0。使用退出码和 `_run.json` 一起验收，不要只看容器是否退出。报告可能包含内部代码信息，应按内部资料控制访问。

## 7. 定时、日志和备份

要每天执行，可在部署账号的 crontab 中配置。先确认 `command -v docker`、`command -v flock` 的实际路径，并确认 cron 使用的时区；下面以系统时区为北京时间、Docker 和 flock 均位于 `/usr/bin` 为例：

```cron
30 1 * * * cd /opt/ai-code-audit && /usr/bin/flock -n /data/ai-code-audit/audit.lock /usr/bin/docker compose run --rm --pull never -T audit >> /data/ai-code-audit/logs/audit-cron.log 2>&1
```

`flock` 只能避免同样使用该锁的任务相互重叠；人工执行扫描时也应使用同一把锁，或者先暂停定时任务并确认已有任务结束。调度器本身按 UTC+8 计算扫描日期；若服务器 cron 不使用北京时间，应调整计划时间。首次上线先手动运行并核对报告，再启用定时任务。

建议在没有扫描任务运行时，按内部备份制度备份 `AUDIT_DATA_DIR/output/`、项目配置及必要的镜像包；恢复时保留相同数据路径和镜像标签。`model.env`、`secrets/` 含明文凭据，应单独加密、限制备份访问权限。`work/` 是扫描专用 Git 副本，可以按需重建；`output/state/` 与历史结果决定增量和复用行为，应一起保留。

运行中的扫描容器可以用 `docker ps --filter label=ai-code-audit=1` 查看。它们由调度器通过 Docker 创建，并非 Compose 直接管理的服务；不要假定 `docker compose down` 会停止这些容器。排查残留时先核实所属任务，再按容器 ID 单独处理。

## 8. 常见问题

| 现象 | 排查方向 |
|---|---|
| 连接不到 Docker daemon | 确认服务已启动、当前账号有 socket 权限，且 `.env` 中 `AUDIT_DOCKER_SOCKET` 是目标机真实路径。 |
| 找不到镜像或尝试访问外网 | `docker image inspect` 检查两个镜像；扫描镜像标签必须与 `.env` 一致，且架构与目标机匹配。 |
| `clone` 失败、认证失败 | 检查 URL、分支、账号只读权限和 `secrets/git-credentials` 中的完整仓库路径；SSH 检查密钥、`known_hosts` 和服务器权限。 |
| 显示 0 个项目 | 检查 CSV 表头、`project_id`、`status=在研` 和 `--only` 参数；0 个项目不一定会返回失败。 |
| 模型连接超时或认证失败 | 从扫描网络检查 DNS、端口、模型基础地址、API Key、模型名及防火墙；`localhost` 不是宿主机地址。 |
| Git 或模型 HTTPS 证书错误 | 内部私有 CA 需分别让调度镜像信任 Git 服务、让扫描镜像信任模型服务；当前模板不自动注入企业 CA，需要按企业证书方案制作内部镜像或扩展配置。 |
| 报告没有更新 | 查看 `_run.json`、`.error.txt` 和日志；无代码与材料变化时可能按规则复用结果，可用 `--only 项目ID --force-full` 重扫。 |
| 扫描中途停止后容器仍在 | 扫描容器是调度器创建的独立容器；用标签查看，确认不属于运行中的任务后按容器 ID 处理。 |

## 9. 升级与回退

升级前停止定时任务并等待当前扫描结束，备份输出状态、配置及旧版镜像包。在联网构建机拉取同一次成功工作流发布的两个指定版本镜像；按第 3 节重新导出、校验、导入，然后检查 `.env` 的两个镜像标签。先对一个项目全量试扫，确认成功后恢复定时。

如需回退，重新导入原先保存的两个镜像并恢复对应 `.env` 和配置，再先运行单项目试扫。`main` 是可变标签，升级前必须留存旧镜像包或使用对应的固定版本标签；仅保留旧的扫描器镜像不足以回退整个部署。
